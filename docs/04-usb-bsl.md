# 04 · USB 设备层与 BSL 协议

## 1. 为什么要自带 USB，而不是借用 FDL1 的函数

早期版本直接调用 FDL1 留在内存里的两个函数（`0x8B50` 发送 / `0x8BDA` 接收）。问题：

| 问题 | 后果 |
|---|---|
| 那两个函数是**绝对地址** | 换任何一个 `fdl1.bin` 就跳进别的代码，直接崩 |
| 单次接收上限 **12 800 字节** | 主机按 16 KB 发 `MIDST_DATA`（16 390 字节）⇒ 整包被丢 ⇒ "一个字节都不回、超时" |

所以本项目自己初始化 USB 控制器、自己做描述符、自己收发。
好处是**缓冲区大小自己定**（32 KB），且不依赖任何闭源组件。

## 2. 控制器

| 项 | 值 |
|---|---|
| 控制基址 | `0x20200000` |
| 端点描述符区 | `0x20201BE0 + n × 32` |
| IN 端点 | **EP5**（地址 `0x85`） |
| OUT 端点 | **EP6**（地址 `0x06`） |
| VID : PID | **`0x1782 : 0x4D00`** |
| 包大小 | 512 字节（枚举阶段可降到 64） |
| 接收缓冲 | **32 768 字节**（`usb_rxbuf`，64 字节对齐） |

### 2.1 初始化

```c
usb_ep_config();    // 写 EP5 / EP6 的类型、包长、使能
usb_start_recv();   // 武装 EP6 的接收描述符
```

`usb_ep_config()` 里的关键写入（`b = 0x20200000`）：

```
b+0x0e = 5   b+0x06 = 0x21  b+0x08 = 0x40      // EP5 配置
b+0x62 = 0x17  b+0x64 = 0x108
b+0x150 = 包长   b+0x152 = 0x48  b+0x153 |= 0x94
b+0x0e = 6   b+0x63 = 0x17  b+0x66 = 8         // EP6 配置
b+0x164 = 包长   b+0x166 = 0x90  b+0x167 |= 0xa8
```

### 2.2 枚举（标准请求）

`usb_sys_events()` 处理控制端点上的标准请求：

| 请求 | 处理 |
|---|---|
| `SET_ADDRESS (5)` | 写地址寄存器 |
| `GET_DESCRIPTOR (6)` | 回设备描述符（`type=1`）或配置描述符（`type=2`） |
| `SET_CONFIGURATION (9)` | 应答 |

设备描述符：`18 01 00 02 00 00 00 40 82 17 00 4d ...`
配置描述符：1 个接口、2 个端点（`0x85` IN / `0x06` OUT），各 512 字节包，`bMaxPower = 0x32`（100 mA）。

## 3. 收发

```
usb_handler()      轮询一次：处理枚举事件 + 检查 EP6 是否有新包
usb_getbyte()      从 usb_rxbuf 取一个字节；取空了就再轮询
usb_recv_frame()   按 0x7E 定界、反转义、校验，凑够一帧返回
usb_send_raw()     填发送描述符 → 触发 → 等完成位（bit18）→ 清标志
```

**为什么接收缓冲要 32 KB**：主机一帧 16 KB + 6 字节头 = 16 390 B。
原来的 12 800（照公开实现抄的）装不下 ⇒ 硬件判定溢出、整包丢弃 ⇒ 表现为"超时"。
缓冲区是我们自己的，直接开到 32 KB。

> 发送完成等待**必须设上限**（代码里 400 万次）。原来是无界等待：
> 一旦发送因故不完成，固件永久停住，主机等 ACK、我们等完成位——双方互等，
> 表现就是"写到一半毫无征兆地停住"。

## 4. BSL 帧格式

```
7E | cmd(2B, BE) | len(2B, BE) | data(len B) | checksum(2B, BE) | 7E
```

- **转义**：data 内的 `0x7E` → `7D 5E`，`0x7D` → `7D 5D`
- **校验**：把 `cmd+len+data` 按 16 位小端字累加 → 回卷两次 → 取反 → 高低字节交换
- **帧长正好是 512 的整数倍时，必须补一个 ZLP**（零长度包），否则主机永远收不完整

## 5. 应答码

| 码 | 含义 |
|---|---|
| `0x80` | ACK |
| `0x81` | VER（版本串） |
| `0x83` | UNKNOWN_COMMAND |
| `0x84` | OPERATION_FAILED |
| `0x8A` | 长度错误 |
| `0x93` | READ_FLASH 数据 |
| `0x96` | INCOMPATIBLE_PARTITION（本项目也用它回 DA_INFO） |
| `0xFF` | LOG（文本） |

## 6. 启动握手：为什么回 `0x96 + DA_INFO`

主机加载完 FDL2 后发 `EXEC_DATA`，FDL1 **不回应答**直接跳转，所以这个 ACK 必须由我们补。
并且**不能只回 `0x80`**：

```
主机逻辑：ret == 0x96 → 解析 DA_INFO；ret != 0x80 → 报 "FDL2 Exec timeout"
```

DA_INFO 声明"存储类型是 NAND"，否则工具会按 eMMC / GPT 处理，后续读写全错。

载荷（`"newt"` + TLV）：

```
id 0 (4B) = 0         bDisableHDLC
id 2 (1B) = 0         bSupportRawData
id 3 (4B) = 0         dwFlushSize
id 6 (4B) = 0x101     dwStorageType = NAND
```

> 必须是**静态常量数组**：运行时逐字节赋值会被编译器合并/重排，字段一错位主机就解析出垃圾。

## 7. ★ 时间预算：1000 ms 是硬约束

PC 侧工具（`spreadtrum_flash` 血统）对普通命令的 ACK 等待是 **1000 ms**，
只有 `erase all` 放宽到 100 s。而它**一帧发 16 KB = 8 页，只等一个 ACK**。

所以固件必须在 1 秒内完成"8 页编程 + 8 页 ECC"：

| 项 | 预算 |
|---|---|
| 8 页编程（mode 20） | ~160 ms |
| 8 页 ECC | ~8 ms |
| **任何一次性初始化** | **不要放在这里** |

历史事故：ECC 表展开（590 万次异或）曾被放在 `cmdset 84` 的第一句，
正好落在主机等 ACK 的那 1 秒里 ⇒ 厂家工具写第一个 16 KB 帧就超时。
现在挪到启动阶段（`main` 第 5 步）。

## 8. 一条命令只回一帧

早期启动时发 `LOG(0xFF) + 0x96` 两帧，实测主机在 exec 处只消费一帧，
剩下那帧变成"下一个命令的应答"，导致整条流水线**错位一格**：

```
START_DATA 收到 0x96、READ_FLASH 收到 0x80、下一个 START 收到 0x93 …
```

现在启动只发一帧（`0x96 + DA_INFO`），LOG 去掉。
**新增应答时务必守住这条**：一条命令 = 一帧应答。

## 9. 命令表

### 标准命令

| 命令 | 名称 | 本项目实现 |
|---|---|---|
| `0x00` | CONNECT | ✅ |
| `0x01` | START_DATA | ✅ 8 B 地址式 + 76 B 分区名式 |
| `0x02` | MIDST_DATA | ✅ 流式攒页，单帧最大 16 KB |
| `0x03` | END_DATA | ✅ 补尾页 + 补写页 0/1 |
| `0x04` | EXEC_DATA | ✅（主要用于自加载场景） |
| `0x05` | NORMAL_RESET | ⚠️ 实现为**关机** |
| `0x06` | READ_FLASH | ✅ 单次 ≤16 KB，支持跨页 |
| `0x0A` | ERASE_FLASH | ✅ 地址式 / 分区名式 |

### 自定义诊断命令（仅本项目使用）

| 命令 | 作用 |
|---|---|
| `0xF0` | 读 NAND 关键寄存器（8 × u32） |
| `0xF1` | 通用 NFI 执行器（8 个 u32 参数） |
| `0xF2` | PHY + NFI 重置 |
| `0xF6` | NFI 寄存器全量回读 |
| `0xF5` / `0xF7` | 只读安全地址 / 只发芯片复位 |
| `0xF8` | 读 dev 结构（208 B） |
| `0xF9` / `0xFA` | 读任意内存 / 调参考固件函数 |
| `0xFB` | 设写模式（0 / 20 等） |
| `0xFC` / `0xFD` | 关 hold / 关擦除（排障用） |
| `0xEE` | 设 OOB 写入字节数（1–128） |
| `0xFE` | 读一页的 OOB |
| `0xE9` / `0xEB` / `0xEF` … | 探针期遗留，见源码注释 |

> 这些命令**不在 BSL 标准里**，只用于本地排障。
> 如果你的工具不认识它们，忽略即可——不影响标准流程。

## 10. 已知缺陷

| 缺陷 | 说明 | 影响 |
|---|---|---|
| **主机断开后端点不重新武装** | 我们只在启动时配置一次端点 | 我们的脚本反复"连接-断开"时会连不上，需重新插拔。厂家工具一次连到底，不受影响 |
| 无串口输出 | 只能靠 USB 诊断命令 | 早期排障困难 |
| 只处理 EP6 的 OUT | 没有实现多端点/中断 | 够用，但不通用 |
