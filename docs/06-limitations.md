# 06 · 已知缺陷与未完成项

> 这一节按"如实"写。看到不完美的地方不必惊讶——它们是真实工作量的一部分，
> 也是后来者可以接手的方向。**动手前先读完，能省你几天。**

## A. 功能边界（设计如此，不是 bug）

| 项 | 现状 | 说明 |
|---|---|---|
| 闪存几何 | **硬编码**：页 2048 / 64 页每块 / 块 128 KB / OOB 78 B | 换一颗不同几何的闪存即失效 |
| 分区 | 只认 3 个（`KernelImg` / `UserImg` / `PreloadUdisk`），块号写死 | 别的分区 ID 直接拒绝（`0x84` / `0x96`） |
| 分区表 | **不解析**，不做一致性校验 | 厂商工具有"分区表不匹配就拒绝"的逻辑，我们没有 |
| FTL / 坏块管理 | **没有** | 直接按物理块读写；坏块靠 ECC 纠正，不做重映射 |
| Flash ID 校验 | **不做** | 不读 ID、不比对；好处是免维护，坏处是换了料不会报错 |
| 擦除粒度 | 整块（128 KB） | 没有部分擦除 |

## B. 已知缺陷（会影响使用）

### B.1 `reset` 只能关机，不能自动重启 ⚠️ 最常被问到

BSL 的 `0x05 NORMAL_RESET` 标准语义是"重启"。本平台实测：

| 尝试 | 结果 |
|---|---|
| `AIRCR (0xE000ED0C) = SYSRESETREQ` | ❌ MMU 关时 data abort 卡死；MMU 开时不动作 |
| PMIC `0x40608C20` **bit1**（注释称"复位"） | ❌ 写完设备不动（APB 不忙，写入确实执行了）。该寄存器 write-only，读回恒 0，**不能拿读回当判据** |
| 按 PMIC 命令序列尝试（`0x40608E24` bit[8:4]=8 → `0x40608C08/0x40608C10 |= 4` → `0x40608060 = 0xE551` → `0x40608048 |= 8/4`） | ❌ 仍不重启 |
| PMIC `0x40608C20` **bit0** | ✅ **关机**（有效） |

⇒ 当前实现：`0x05` = 置 `0x40608C20` bit0，**关机**。

**这是明确的遗憾**：同平台的厂商工具能自动重启，说明这条路存在，只是我们没打通
（线索：`0xE551` 那条 PMIC 命令可能还需要配套的上层通知或 I2C 时序）。

### B.2 主机断开后 USB 端点不会重新武装

现象：脚本退出一次后，再连就连不上，必须重新插拔设备。

原因：USB 层只在启动时 `usb_ep_config()` 一次，
没有处理"总线复位 / 重新 SET_CONFIGURATION 后重新武装端点"。

影响：**厂家工具一次连到底，不受影响**；自己的脚本反复操作会撞上。

修法（未做）：在 `usb_sys_events()` 处理 `SET_CONFIGURATION` 时重新配置端点；
或在主循环检测到端点 halt 时复位端点。

### B.3 没有串口输出

固件没有任何 UART 打印。排障只能靠 USB 自定义命令回传数据。
早期为打通 UART 花了时间，最后放弃——这也是为什么代码里保留了一批诊断命令。

### B.4 写后不校验

固件**不回读校验**写入内容。要确认写对了，必须由主机侧读回比对，
或者靠"设备能不能开机"来判断。

### B.5 速度仍比同平台厂商工具慢约 4 倍

| | 写一页 | 8.96 MB |
|---|---|---|
| 厂商工具 | ~0.8 ms | 3.6 s |
| 本项目 | **3.58 ms** | ~15 s |

原因：每页仍是"4 扇区 × (LOAD + EXECUTE)"，事务数偏多；
厂商工具在同平台上的实现细节未完全还原。**不影响正确性，只影响时间。**

### B.6 代码组织

- `main.c` 约 4600 行，是**单文件**实现（历史上是从一个巨型文件里裁剪出来的）；
- 保留了一批探针期（probe）遗留的诊断命令 `0xE1–0xFF`，部分语义只有原作者清楚；
- 链接脚本会把代码和数据放在同一个 LOAD 段，链接器会警告 **RWX segment**（不影响运行）。

## D. 已证伪的尝试（**不要再试**）

这一节是本项目最贵的资产：每条都真实踩过。

| # | 试图 | 实测结果 |
|---|---|---|
| 1 | 补 NFI ECC 寄存器（`0x60–0x6C` / `0x21C` / `0xB0–0xBC`）让控制器生成 ECC | 三种配置全失败：OOB 仍全 `FF`，其中一种**控制器挂死** |
| 2 | `SET FEATURE(0xB0)=0x19` 开芯片片上 ECC | 写 8 页读回 **OOB 仍全 `FF`** |
| 3 | 单事务多拍（cfg 高字节塞扇区数 / 描述符 `0x2800`、`0x2E00` / `NFI[8]` 塞整页长度） | **全部超时**，一个字节不写 |
| 4 | 直接调 `cmdset 46` 写页 | 写出来永远是 `FF`，必须走 `cmdset 84` |
| 5 | 认为"主机直发 `cmdset 18` 等于 SET_FEATURE(0xB0)" | 错：`nf_exec` 里有专门分支，跑的是另一套序列 |
| 6 | 砍掉每扇区状态轮询、用固定延时提速 | **写坏页**（`tPROG` > 1 ms，延时替代不了轮询） |
| 7 | 用 8 页小测试判断写入正确性 | **会误报**：页 0/1 后写会干扰，必须整块 64 页、按 `[2..63,1,0]` |
| 8 | 把 8193 列 ECC 映射压成"一个生成多项式" | 不是简单循环码（Toeplitz 31 % 不符、多项式 gcd 互质），只能整表递推压缩 |
| 9 | 靠 12 800 字节的接收缓冲吃 16 KB 帧 | 整包被丢弃，表现为"超时"。必须 ≥16 390 |
| 10 | 先写页 0 再写页 1 | 页 1 的编程会扰动页 0 ⇒ 页 0 出整字节错。**必须 1 → 0** |
| 11 | `AIRCR` 写 `0x05FA0004` 复位 | 见 B.1，无效 |

## E. 安全边界：什么情况下会变砖

| 场景 | 后果 | 可恢复 |
|---|---|---|
| 写入中途拔线 / 断电 | 分区半写，设备起不来 | ✅ 重刷即可 |
| 工具报错后停止 | 同上 | ✅ |
| 闪存几何与假设不符（**换了料**） | 地址算错，**可能覆盖其它分区** | ⚠️ 取决于覆盖了什么；若碰到 BOOT/VBM 就麻烦 |
| 能枚举 `VID_1782` | 一定能救 | ✅ |
| 枚举不出来 | 继续按住 RESET 上电 | 一般能救 |

**本项目不写 BOOT0 / BOOT1 / VBM**（只碰块 79–134、135–203、210–247），
这是"不会彻底变砖"的根本原因。**但前提是几何假设成立。**
