# 07 · 移植指引

> 本实现是**针对一颗 SoC + 一颗闪存 + 一份分区表**写的。移植不是"改几个宏"那么简单，
> 但也不需要重写——下面按改动量从小到大排。

## 0. 先判断你属于哪种情况

| 情况 | 工作量 | 见 |
|---|---|---|
| 同一 SoC，换**同几何**闪存（仅容量不同） | 几小时 | §1 |
| 同一 SoC，换**不同几何/OOB** 的闪存 | 半天 ~ 一天 | §2 |
| 同一 SoC，**分区布局不同** | 1 小时 | §3 |
| **换 SoC** | 几天，接近重做 | §4 |

## 1. 同几何、不同容量

如果新闪存仍是：页 2048 / 64 页每块 / 块 128 KB / OOB 78 B，只是总容量不同：

- **容量更大**：不用改。本实现只用块 79–247（约 31.75 MB），多出来的块用不到。
- **容量更小**（块数 < 248）：会失败（UserImg / Preload 越界）。此时要改分区表（§3），
  或者干脆换料。

## 2. 同 SoC、不同几何

要改的地方（都在 `src/main.c`）：

| 位置 | 改什么 |
|---|---|
| `PAGE_SZ` `PAGES_PER_BLK` `BLK_SZ` | 页大小、每块页数 |
| `g_wr_sector` / 扇区循环次数 | 每页扇区数（2048/512 = 4） |
| `g_oob_wlen`（默认 64/78） | 备用区字节数 |
| `NFI[0x008]` 的长度编码 | `0x3000 \| (字节数-1) \| (OOB-1)<<16` |
| `ecc_fill_oob()` | OOB 结构（每段长度、校验位位置） |
| `src/ecc_tab.h` | 新的 ECC 映射（见 §2.1） |
| 时序寄存器 `NFI[0x014]/[0x018]` | 新芯片的 tPROG/tR 等 |
| `g_parts[]` | 分区块号 |

### 2.1 ECC 怎么办

分两种：

- **控制器 ECC 配置不变、只是 OOB 布局不同** ⇒ 同一套 224 位映射大概率仍适用，
  只需改 `ecc_fill_oob()` 里的字节摆放；
- **纠错强度变了**（`NFI[0x0B0/0x0B4]`、`NFI[0x00C]` 改了）⇒ 映射要**重新解**：
  采样新设备真实 OOB → 在 GF(2) 上解线性方程组 → 用 `tools/gen_ecc_tab.py` 生成新表。

> 解映射的工具链思路见 `docs/03-ecc.md` §3.2。这一步没有现成脚本（采样与求解是离线做的），
> 需要的话可以按文档自己实现，工作量约 1–2 天。

## 3. 分区布局不同

只改 `g_parts[]`：

```c
static const part_t g_parts[] = {
    { PART_KERNEL,   79u, 56u },   /* 起始块, 块数 */
    { PART_USER,    135u, 69u },
    { PART_PRELOAD, 210u, 38u },
};
```

同时确认：

- `PART_xxx` 的 ID 与主机的 `Base:` 值一致（`0x80000003/4/8`）；
- 分区**不跨越 256 块**；
- 分区之间不重叠（尤其别碰到 VBM / BOOT）。

## 4. 换 SoC

需要改的是一整组地址：

| 模块 | 当前值 | 说明 |
|---|---|---|
| NFI 控制器 | `0x21A00000` | 换 SoC 必变 |
| NFI 复位 | `0x20E00000` | |
| 时钟门控 | `0x21500000`（`+0x60`、`+0x24`） | |
| NAND PHY | `0x402E0000`、`0x402A00xx`、`0x402A05xx` | 一整批寄存器，需重新对照 |
| PMIC / APB | `0x40600000`、`0x40608C20`、`0x40608E14` | 关机/电源 |
| USB 控制器 | `0x20200000`、端点区 `0x20201BE0` | |
| 内存布局 | `DBUF 0x80298820`、`OBUF 0x80176000` | 需确认新平台可用 RAM |
| 栈 | `0x80010000` | |
| MMU 映射范围 | `0x80000000–0x803FFFFF` | 按实际 RAM 调整 |

另外，**ECC 几乎肯定要重新解**（不同代控制器算法不同），USB 描述符也可能要改。

## 5. 移植后的验证顺序（别跳步）

```
① 只上电 + 关机         —— 证明能被加载、能跑 C 代码
② 读一页（已知内容）    —— 证明 NFI 初始化 + 读路径正确
③ 读一页的 OOB          —— 证明 ECC 布局/解码对
④ 擦一个块 + 读回全 FF  —— 证明擦除路径
⑤ 写一个块 + 读回比对   —— 证明写路径 + ECC
⑥ 写整分区 + 开机       —— 端到端
```

每一步都**只用空闲块**，不要一上来就动正式分区。

## 6. 移植时最容易踩的坑

| 坑 | 现象 |
|---|---|
| `NFI[0x008]` 写成页大小 | 永久挂在 `START = 0x40000000` |
| `NFI[0x000]` 写 burst 值 | 事务不启动 |
| 一次性初始化放在写页路径 | 主机 1000 ms 超时 |
| 备用区按 64 B 处理 | 设备起不来（这颗是 78 B） |
| 页 0/1 先写 | 页 0 出整字节错 |
| MMU 段属性写错（AP=00） | 第一次访问 MMIO 就异常，固件在回 ACK 前死掉 |
| 用 `strip`/`-O2` 大幅改动 | 破坏时序敏感代码；本项目用 `-Os` 且未 strip 符号（.bin 本身无符号） |

## 7. 如果你只想"读懂"而不移植

建议顺序：`docs/01` → `docs/02` → `src/main.c` 里的 `nf_exec` → `docs/03`。
`nf_exec` 是全部硬件交互的汇总点，看懂它基本就懂了这颗控制器。
